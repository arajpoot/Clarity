Governance contract

Binding rules for the Clarity castle. This is a discovery document — it does not replace Companion, Yawm, University, Amānah, or Craft, and it does not rewrite their navigation. Room apps may be stricter; they may not be weaker.

1. Identity

What Clarity is: a private, educational companion for learning and remembrance.

What Clarity is not: a fatwa desk, a court, a bank, a seminary, a grade of īmān, or a substitute for a living teacher you trust.

2. Core submission rules

  1. Arabic on top where Qur’ān text is shown. Translation is a bridge, not a replacement.
  2. No practice card without a citation the user can open (āyah reference or collection · number).
  3. Do not say “the Sunnah is…” when you mean “this report in Bukhārī / Muslim …” — name the report.
  4. Do not mix ranks: Qur’ān, ṣaḥīḥ reports, and optional media must not share the same visual tier.
  5. When two ṣaḥīḥ reports need fiqh to reconcile: print both and send the user to a scholar. Do not invent a third source called Clarity.
  6. Night and grave-facing content stays Qur’ān, ṣaḥīḥ, death-awareness, and istighfār — not entertainment sīrah.

3. Sources policy

  • Quran.com — Qur’ān text and translations
  • Sunnah.com — hadith collections with numbers
  • Prefer collection · number · grade when a report is shown as evidence.
  • If a grade is not loaded: say so honestly and link the source page.
  • Do not present machine translation as an official tafsīr.

4. Privacy & on-device data

  • Sensitive Amānah material is designed to stay on this device where implemented that way.
  • Clarity does not store your vault passphrase on Clarity servers.
  • Private trust notes are not published as public web pages.
  • Use a strong device passcode; back up anything important with a method you control.
  • Treat educational screens as learning aids — not court filings.

5. Visibility & richness clauses

These protect the user from “empty shell” upgrades and accidental hide-states. They bind Companion especially; other rooms should not regress them.

Visibility

  • §V1 — Mounted work must be seeable. Content that belongs on the active tab/path must not sit at display:none, zero height, or near-zero opacity because of a stray style or parent chain.
  • §V2 — Path lock ≠ hard wipe. Hiding sections for an educational path is allowed. Silently destroying markup, canvas, or media hosts is not.
  • §V3 — Media hosts stay dimensional. Meme stage/canvas and reflection media frames keep a real minimum height when their section is legitimately open.
  • §V4 — Details may open for access. Enrichment held in details elements may be opened by foundation scripts so the user can reach what the tab promises.

Richness

  • §R1 — Intro honesty. Section counts and pathway blurbs must match what the active path/tab actually offers — not a global maximum.
  • §R2 — Enrichment holds. Reflection / deep-hold / archive layers exist to preserve curated richness across deploys. An upgrade may refine them; it may not blank them without a named migration.
  • §R3 — Engines rehydrate. Tab HTML injected into the mount must re-run its scripts (Campus-style mount fortify). A pretty shell with dead engines is a failed deploy.
  • §R4 — Craft boundaries. Meme and heavy craft desks respect path governance and Craft’s media charter; they must not flash into Seeker-only views.

6. Companion foundation (Campus-grade)

University keeps a charter and ordered stages so progress is not a random pile of pages. Companion keeps a foundation seal and layered modules so reminder work is not one fragile file.

  • Seal: data-companion-foundation-seal="v1" and data-clarity-room="companion" mark the shell.
  • Own asset graph: Companion lives under /companion/ + /companion/assets/ — not inside another room’s bundle.
  • Path governance: Seeker → New Muslim → Daily Muslim → Aspiring Daʿī are educational tracks, not ranks of īmān.
  • Mount fortify: tab mount re-inserts scripts and dispatches mount events so hydrators run.
  • Visibility foundation + hold-fix: protect richness after style/path races.
  • Integrity pass: cards outside the active path stay gated; vault/craft boundaries respected.
  • Archive layers: versioned archive/enrich modules may stack; newer layers refine, older layers are not deleted casually.

Operator note: offline pulls and deploys should ship the seal, shell, path governance, mount fortify, visibility foundation, and integrity modules together.

7. Upgrade & preserve rules

No upgrade may cause loss of all Companion work in place.

  1. Additive first. Prefer new versioned files (*-v2.js) over silent overwrite of foundation modules.
  2. Never strip the seal without a documented major foundation bump and migration notes.
  3. Cache honesty. Service worker and CDN query strings must allow users to receive the new layer without wiping unrelated room caches.
  4. Path progress stays on-device. Unlock keys and notes in localStorage are user data — do not rename keys without a read-migrate-write step.
  5. Rollback is a feature. Keeping a prior asset version query (or archive folder) is preferred to “delete and hope.”
  6. Room isolation. A Companion deploy must not require wiping Yawm, Campus, Amānah, or Craft.
  7. Empty shell is a defect. If a tab title promises sections the user cannot open or see, the deploy fails §R1 / §V1.

9. Room charters (summary)

Campus · University

  • Not a physical university or accredited degree; not a grade of īmān.
  • Not affiliated with Al-Azhar, Madinah, IIUM, or any named institution.
  • Full text: Charter · room: University.

Craft · Media daʿwah

  • Scripture lines from governed packs — not free-type as revelation.
  • Scenery discipline; shariah scan on remote backgrounds; educational stamp on export.
  • Workbench: Meme Studio.

Amānah · Trust desk

  • Optional on-device passphrase; not a bank, court will, or inheritance order.

Companion · Pathways

  • Four doors are educational tracks; ordered quiz/unlock is a study ladder, not a certificate.
  • Section visibility matches the active path — tools must not silently reopen locked desks.

10. What “done” looks like

  • Hear this — Qur’ān / ṣaḥīḥ with a path to verify.
  • Obey this — one clear educational action, not a private ruling.
  • Send it ahead — deeds and notes that stay on the device unless exported.

They never need a madhhab picker to use the home screen. Companion richness remains visible after upgrades.

11. Change control

  • This page consolidates policy. Room apps keep their own code and nav.
  • Stricter room rules are allowed; weaker ones are not.
  • If a feature cannot name its source, keep private data local, or preserve Companion foundation modules, it does not ship under Clarity’s name.
