## 1. Purpose

This seal does the same for **Companion**: future upgrades must be **additive, targeted, and reversible** — never a single-pass wipe of shell, tabs, meme SoT, or Archive3 chrome.

## 3. Upgrade law (future tickets)

Every Companion ticket **must**:

1. Open and close with **Bismillah**.
2. Declare **scope paths** (file list) before edit.
3. Default `enrichment: held` for every surface not in scope.
4. Prefer **additive** patches over full-file rewrites of tab bodies.
5. Forbid “rebuild Companion from scratch” without an explicit **foundation-exception** ticket that:
   - lists every protected layer above,
   - provides migration links for any moved capability,
   - passes §3 + §3A smoke **before** merge.
6. Run smoke at least on: shell, active tab(s), `/companion/meme/`, redirects door.
7. Changelog row: `enrichment:` + `visibility:` tags.

### Forbidden patterns (destroy-in-one-go)

- Replacing all six tab HTML files with stubs or a single thin template  
- Stripping Archive3 folders to empty  
- Re-loading global `companion-meme-paint` / dual spine on shell  
- Turning redirects/meme into a second full studio  
- Path governance that `display:none`s educational cards by default  
- “Campus parity” used to justify deleting Companion content  

### Allowed patterns

- Single-owner allowlist changes inside `/companion/meme/`  
- Additive glory rails, deep-learning strips, CSS soak layers  
- Targeted dedupe of **duplicate ids/titles** (keep one full copy)  
- Progressive disclosure (`<details>`) without deleting body
